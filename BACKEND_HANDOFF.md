## Important Context

The `analysis/` folder is important and should not be deleted unless the backend is changed to no longer depend on it. The seed script reads `analysis/seed-data.json`, and the backend docs/inference notes reference the analysis specs.

Some endpoints were inferred from `analysis/route-map.json` because they were present in frontend actions but absent from `analysis/api-spec.json`. Those are documented in `backend/analysis-inference.md` and marked in code with `TODO: VERIFY_INFERENCE`.

## Files Added

### Analysis Files

- `analysis/api-spec.json`
  - Authoritative API endpoint specification used to build controllers, routes, validation, auth rules, and expected responses.

- `analysis/db-schema.json`
  - Authoritative MongoDB/Mongoose schema source. It defines collections, fields, enums, references, required fields, and indexes.

- `analysis/route-map.json`
  - Maps frontend pages/actions to backend endpoints. Used to catch endpoints referenced by the UI but missing from the API spec.

- `analysis/seed-data.json`
  - Seed data for demo users, research projects, meetings, and system settings. Used directly by `backend/src/seed/seed.js`.

- `analysis/frontend-integration-snippets.md`
  - Frontend integration guidance generated from analysis. Useful when connecting React pages to the backend API.

- `analysis/readme.md`
  - Human-readable explanation of the analysis folder and migration plan.

### Backend Root Files

- `backend/package.json`
  - Defines dependencies and scripts:
    - `npm start`: runs `src/server.js`
    - `npm run dev`: runs with nodemon
    - `npm run seed`: loads data from `analysis/seed-data.json`
    - `npm test`: runs Jest/Supertest tests
    - `npm run lint`: syntax-checks key server files

- `backend/package-lock.json`
  - Locked npm dependency versions generated by install.

- `backend/.env.example`
  - Example environment variables for MongoDB, JWT, CORS, uploads, and future S3 settings.

- `backend/.gitignore`
  - Ignores `node_modules`, local env files, coverage, and uploaded files while keeping `uploads/.gitkeep`.

- `backend/README.md`
  - Developer instructions for install, run, seed, test, environment setup, frontend integration, and PR pushing.

- `backend/analysis-inference.md`
  - Documents inferred behavior and verification notes. Start here before changing route-map-only endpoints.

- `backend/scripts/start.sh`
  - Small shell script to start the backend from the `backend/` directory.

- `backend/uploads/.gitkeep`
  - Keeps the upload folder structure in Git while actual uploaded files remain ignored.

### Express App And Server

- `backend/src/app.js`
  - Builds the Express app.
  - Adds security, CORS, JSON parsing, logging, static upload serving, health route, API route mounting, 404 handler, and error handler.

- `backend/src/server.js`
  - Runtime entry point.
  - Loads env, connects to MongoDB, and starts the HTTP server.

- `backend/src/config/db.js`
  - Exports `connectDB()`, the Mongoose connection helper.

### Models

- `backend/src/models/User.model.js`
  - Mongoose model for users.
  - Handles roles, account status, scholar-supervisor assignment, password hashing, password comparison, and public JSON formatting.

- `backend/src/models/ResearchProject.model.js`
  - Mongoose model for research projects.
  - Tracks scholar/supervisor refs, topic, department, stage, progress, and status.

- `backend/src/models/Submission.model.js`
  - Mongoose model for synopsis/thesis submissions.
  - Stores scholar info, topic, file URL, type, status, remarks, and submission timestamp.

- `backend/src/models/Meeting.model.js`
  - Mongoose model for meetings, viva sessions, panels, venue, date/time, supervisor, and status.

- `backend/src/models/Minute.model.js`
  - Mongoose model for DRC meeting minutes, agenda, decisions, writer, and signature status.

- `backend/src/models/SystemSetting.model.js`
  - Mongoose model for university/system-level settings used by seed data.

### Middlewares

- `backend/src/middlewares/auth.js`
  - Exports `authenticate()` and `authorize(allowedRoles)`.
  - Reads `Authorization: Bearer <token>`, validates JWT, checks active user, and attaches `req.user = { id, role }`.

- `backend/src/middlewares/errorHandler.js`
  - Defines `AppError`, `asyncHandler`, `notFound`, and centralized JSON error responses.

### Validation And Services

- `backend/src/utils/validators.js`
  - Joi validation schemas for login, users, research, submissions, meetings, minutes, reports, params, and queries.
  - Exports middleware helper `validate(schema, source)`.

- `backend/src/services/storageService.js`
  - Local Multer upload storage.
  - Validates file extension and size.
  - Generates public `/uploads/...` paths.
  - Includes an S3 adapter stub for future object storage work.

### Controllers

- `backend/src/controllers/auth.controller.js`
  - Implements `/api/auth/login`.
  - Verifies email, password, role, active status, and returns JWT plus user profile.

- `backend/src/controllers/users.controller.js`
  - Implements user list/create/update/delete.
  - Implements scholar supervisor assignment and unassignment.

- `backend/src/controllers/research.controller.js`
  - Implements research list/create/update/delete.
  - Resolves scholar and supervisor ObjectIds from names where the API spec sends names but the DB schema requires refs.

- `backend/src/controllers/submissions.controller.js`
  - Implements synopsis upload, thesis upload, and synopsis status update.
  - Thesis upload is route-map-inferred and needs product verification.

- `backend/src/controllers/meetings.controller.js`
  - Implements meeting list/create/update/delete.

- `backend/src/controllers/minutes.controller.js`
  - Implements minutes list/create.

- `backend/src/controllers/reports.controller.js`
  - Implements route-map-inferred report endpoints:
    - scholar search report
    - aggregate generated report
  - Needs product verification because these endpoints were not in `analysis/api-spec.json`.

### Routes

- `backend/src/routes/auth.routes.js`
  - Mounts auth login under `/api/auth`.

- `backend/src/routes/users.routes.js`
  - Mounts protected user routes under `/api/users`.
  - Enforces admin/HOD/admin-only access based on endpoint.

- `backend/src/routes/research.routes.js`
  - Mounts protected research routes under `/api/research`.

- `backend/src/routes/submissions.routes.js`
  - Mounts protected upload/status routes under `/api/submissions`.
  - Uses Multer upload middleware for synopsis and thesis files.

- `backend/src/routes/meetings.routes.js`
  - Mounts protected meeting routes under `/api/meetings`.

- `backend/src/routes/minutes.routes.js`
  - Mounts protected minutes routes under `/api/minutes`.

- `backend/src/routes/reports.routes.js`
  - Mounts protected inferred report routes under `/api/reports`.

### Seed And Tests

- `backend/src/seed/seed.js`
  - Reads `analysis/seed-data.json`.
  - Hashes known demo passwords.
  - Upserts users, research projects, meetings, and system settings.
  - Demo passwords are listed in `backend/README.md`.

- `backend/tests/api.test.js`
  - Jest/Supertest integration tests.
  - Uses `mongodb-memory-server` by default.
  - Tests auth login, protected research creation, and research listing.

## Where The Next AI Should Start

1. Read `backend/analysis-inference.md`.
   - It explains what was inferred and what needs confirmation.

2. Read `analysis/api-spec.json`, `analysis/db-schema.json`, and `analysis/route-map.json`.
   - These are the sources of truth for intended backend behavior.

3. Run validation:
   - `cd backend`
   - `npm install`
   - `npm test`
   - `npm run lint`

4. If continuing backend implementation, start with:
   - Add missing GET/list endpoints if the frontend needs them beyond the generated ones.
   - Verify inferred thesis/report endpoints with product expectations.
   - Connect frontend API calls to `/api`.
   - Replace local upload storage with S3 if deployment requires it.
   - Add more tests for users, uploads, meetings, minutes, and authorization failures.

5. If deploying:
   - Create `backend/.env` from `backend/.env.example`.
   - Set a strong `JWT_SECRET`.
   - Configure production `MONGO_URI`.
   - Decide upload strategy: local disk or S3-compatible storage.

## Known Cautions

- Do not commit `.env`, `node_modules`, or real uploaded files.
- Do not delete `analysis/` unless `backend/src/seed/seed.js` is changed to use another seed source.
- `JWT_SECRET` falls back to a development string if missing; production must set it explicitly.
- `mongodb-memory-server` can require network access to download MongoDB binaries in fresh environments.
